A Practical Framework for LLM Evaluation模型评测：从模型能力到真实应用的系统化闭环

A concise, product-oriented framework for deciding what to evaluate, how to evaluate it, and when an AI system is ready for real users.

By Serena Song 宋月Original article in ChineseJuly 2026
A useful evaluation system is not a leaderboard. It is a continuous loop from goals and definitions to methods, evidence, release decisions, and reusable organizational knowledge.
01

Three levels of evaluation

Evaluation should follow AI capability from its raw foundation to its final product form. Each level asks a different question, requires different evidence, and supports a different decision.

01Model architecture

Can the AI do it? Measure raw intelligence: knowledge, reasoning, language, long-context recall, hallucination, and safety before tools or task-specific optimization.

02Capability engineering

Can intelligence become a stable function? Evaluate task performance, RAG retrieval, tool use, robustness, latency, and failure handling.

03Application & scenario

Does it create user and business value? Evaluate task completion, usability, satisfaction, retention, cost per task, and actual workflow outcomes.

02

The evaluation workflow

A complex, open-ended question becomes actionable when it is decomposed into three decisions: what matters, how evidence will be produced, and what threshold counts as success.

What to evaluate

Dimensions & modes

Define the target capability, evaluation scope, task setting, and whether the goal is professional benchmarking, comparison, or practical acceptance.

How to evaluate

Methods & data

Combine objective automation, human review, and LLM-based judging with public benchmarks, custom test sets, or third-party data.

How good is enough

Metrics & baselines

Choose measurable criteria and compare against human performance, industry state of the art, or explicit product release requirements.

03

Match the mode to the lifecycle

The article distinguishes three complementary evaluation modes. Their importance changes as a model moves from research to productization and delivery.

Mode
Primary question
Best used for
Professional
Does the model meet a standardized capability baseline?
Research, capability analysis, pre-iteration checks
Comparative
Where does a model or version outperform or underperform alternatives?
Model selection, competitive analysis, product positioning
Practical
Is the system useful, stable, safe, and understandable in a real workflow?
Pre-launch acceptance and continuous product improvement
04

Use multiple evaluation methods

Objective

Automated metrics

Compare outputs with reference answers using deterministic rules or metrics such as accuracy, F1, BLEU, and ROUGE. Best for structured tasks with clear ground truth.

Subjective

Human evaluation

Experts judge fluency, logic, relevance, consistency, and user experience. This remains essential for open generation and domain-sensitive quality.

Scalable

LLM-as-a-Judge

A stronger or specialized model scores outputs against explicit rubrics. Reliability improves through examples, structured output, repeated judging, voting, and human calibration.

Important limitation: LLM judges can exhibit length, position, and style bias. A robust system combines model judging with human expert review instead of treating automated scores as ground truth.
05

Evaluator + aggregator

The article's most product-relevant contribution is a two-part automated architecture. Individual evaluators produce evidence; an aggregator turns that evidence into a decision that can be checked against people and real behavior.

Evaluators

Score each quality dimension and explain the score.

  • Prompt + LLM for flexible rubrics
  • Fine-tuned judges for stable, specialized standards
  • Rule systems for precise quantitative checks
  • Test system prompt, model, and tools as a combined environment
→

Aggregator

Map many automated signals to a smaller set of trusted release indicators.

  • Align machine scores with human labels
  • Fit category-specific weights or data-driven models
  • Support Good / Same / Bad and release decisions
  • Recalibrate as products and users change
The alignment loop
  1. Calculate Pearson or Spearman correlation between machine metrics and human evaluation.
  2. Select the machine signals most predictive of each human quality dimension.
  3. Use category-aware weighting, regression, decision trees, or clustering to fit final scores.
  4. Monitor correlation over time and replace evaluators when alignment declines.
06

Datasets and metrics

Public benchmarks enable standardized comparison, while custom datasets capture the realities of a specific product. Strong evaluation programs use both.

Public benchmarks

Knowledge and Chinese capability: MMLU, C-Eval, CMMLU. Reasoning and general ability: HellaSwag, ARC, OpenBookQA, ANLI, BBH, AGIEval. Math, dialogue, code, and safety: GSM8K, MATH, MT-Bench, HumanEval, MBPP, TruthfulQA, PromptBench.

Custom evaluation sets

Start from product requirements, collect representative and difficult cases, clean and extend the data, define expert labels, and preserve a small golden set for calibration and regression testing.

Objective indicators

Accuracy, precision, recall, F1, BLEU, ROUGE, task completion, retrieval accuracy, latency, error rate, and cost per task.

Subjective indicators

Fluency, logic, relevance, consistency, usefulness, safety, user experience, expert preference, and satisfaction.

07

Core takeaways

01

Evaluate the system, not only the model

Application quality emerges from the interaction of prompts, models, tools, data, and user workflows.

02

Connect scores to real outcomes

Automated evaluation becomes meaningful only when it predicts expert judgment or observable user and business behavior.

03

Treat evaluation as infrastructure

A reusable SOP, golden dataset, regression process, and feedback loop let evaluation drive continuous model and product evolution.
